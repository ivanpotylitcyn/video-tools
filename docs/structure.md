# Структура и принципы

## Назначение

Разработка и личное использование Иваном. Предпочитаем локальную офлайн-работу.
Публичная упаковка и монетизация не определяют текущую структуру.

## Иерархия

```text
tools/transcribe/                         # независимый инструмент расшифровки
resolve/fusion/templates/effects/<имя>/   # эффекты Fusion
resolve/fusion/templates/generators/<имя>/# генераторы Fusion
docs/workflows/                          # повторяемые процессы
docs/structure.md                        # актуальные правила устройства проекта
scratchpad/                              # временные пробы вне Git
```

Resolve — самостоятельное направление в корне. Внутри будущие соседние ветки:
`timelines/`, `markers/`, `color/`. В Fusion по мере необходимости появятся
Titles и Transitions. Названия Fusion Templates, Effects, Generators, Titles,
Transitions соответствуют [руководству Blackmagic](https://documents.blackmagicdesign.com/UserManuals/FusionManual.pdf).
`.setting` — расширение, не название всей категории инструментов.

Для небольшого инструмента реализация лежит рядом с README. `src/`, `examples/`
и дополнительные документы добавляются по необходимости. Общие установочные
операции переиспользуются; настройки конкретного инструмента остаются в его папке.
Независимые от Resolve субтитры, звук и рендер не помещать в Resolve только потому,
что их результаты затем можно туда импортировать.

## Языки

Bash управляет готовыми программами и простыми конвейерами. Python обрабатывает
данные, сложные условия, форматы и таймкоды. Оба языка равноправны; действующие
реализации не переписываются ради единообразия языка. Ruby-сборщик Type Drift
сохранён как рабочий исходник; Ruby требуется только разработчику для пересборки.

## Платформы и установка

Переносимую основу закладываем сразу, фактическую поддержку подтверждаем проверками.
Пути передавать аргументами, не зашивать домашние каталоги, ОС-зависимые операции
отделять. Установка повторяема, не заменяет чужие файлы и не запускает обработку.
Модели и зависимости не загружать скрытно при обычном запуске.

macOS — проверенная рабочая среда. Linux и Windows пока не проверены.
Windows Terminal рекомендуем как интерфейс терминала, но не обязательную зависимость.
Он не устанавливает Bash. Для Windows ещё предстоит выбрать и проверить основной
маршрут: PowerShell для нативных Python-команд, WSL или Git Bash для Bash-сценариев.
Примеры должны указывать оболочку; одной маркировки «Windows Terminal» недостаточно.

## Будущий `vt` и Python-окружение

Единый интерфейс планируется; пока использовать существующие команды из README.
Один `.venv` на репозиторий, вне Git, вводим с первой внешней Python-зависимостью.
Запуск `vt` будет использовать интерпретатор окружения без ручной активации.
Настройка проверяет версию Python, создаёт окружение и ставит закреплённые зависимости;
`doctor` проверяет также ffmpeg, Whisper и модели. `venv` сам Python не устанавливает.
Управление Python через `uv` пока не принято как обязательная зависимость.
Пустой requirements.txt и окружение без нужды не создаём.

## Установка шаблонов

Все шаблоны устанавливаются одинаково: `Templates/Edit/<категория>/vt/<имя>.setting`.
Группа `vt` используется для Effects, Generators и будущих Titles/Transitions.
Установщики инструментов вызывают общий помощник и создают прямые симлинки на
реализацию в репозитории. Явная папка назначения используется без изменений.
Чужие файлы не заменяются; повторный запуск безопасен.

## Команды

Команды запуска находятся в README и документации инструментов. Индивидуальные
обёртки в корне репозитория не добавлять. Когда появится потребность в общем
интерфейсе, использовать одну команду `vt` с тематическими подкомандами.
Общие установочные проверки держать в одном помощнике; установщик инструмента
задаёт его шаблон и категорию.
