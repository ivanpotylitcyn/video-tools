# Как создаём инструменты

## Путь от задачи к инструменту

1. Определить конкретный результат, входы, выходы и критерий проверки.
2. Проверить имеющееся: каталог README и подходящие инструменты. Новую идею
   записать в ROADMAP, если она не относится к текущей задаче.
3. Сделать короткую пробу в `scratchpad/`. Проектные решения вести в папке проекта.
4. Оценить результат. Решить: оставить разовым решением, обобщить, отложить или прекратить.
5. При обобщении убрать параметры конкретного ролика из кода, дать инструменту
   собственную папку, короткую команду, инструкцию и нужные проверки.
6. Обновить каталог и план; явно назвать, что ещё не проверено Иваном.
7. При переводе в «Готов» выполнить очистку документации по списку ниже.

Одновременно ведём один основной результат из раздела «Сейчас».
Эксперимент не обязан становиться общим инструментом.

## README инструмента

Назначение → статус и основание → требования и проверенные платформы → установка,
если нужна → минимальная команда и результат → ограничения → разработка и проверка.
Добавлять небольшой пример, когда он помогает; частные материалы не использовать
как распространяемые примеры. Проверки структуры не заменяют просмотра и слуховой оценки.

## Проверки

Проверять то, что затрагивает изменение. Для файловых перестановок — команды,
относительные пути, ссылки и сохранность данных. Для форматов и вычислений —
содержательные проверки результата. Шаблоны Fusion требуют просмотра и рендера
в Resolve Иваном. Не писать тесты, которые лишь повторяют реализацию.

Медиаобработку агент запускает только в `scratchpad/` на коротких клипах-ссылках.
Реальные папки разрешены только для `-n`. Результаты теста не должны уходить через
ссылку на реальную папку. Боевые команды передаются Ивану.

## Готовность

- **Эксперимент:** ищем подход, интерфейс может меняться.
- **На проверке:** реализация есть, названа конкретная оставшаяся проверка.
- **Готов:** пройден рабочий сценарий, есть инструкция и воспроизводимый запуск.

Готовность и переносимость независимы: готовый на macOS инструмент может быть
ещё не проверен на Windows/Linux. Указывать проверенную среду и незакрытые проверки.

## Перевод в «Готов»

- README содержит действующие команды, требования, ограничения и статус.
- Технические документы описывают текущую реализацию и условия корректной работы.
- Рабочие заметки, даты изменений, отвергнутые варианты и причины выбора убраны;
  история решений остаётся в коммитах.
- Завершённые задачи удалены из ROADMAP, оставлены только текущие и будущие.
- Ссылки и примеры соответствуют действующим путям; временные файлы убраны.
- Историю в Git не создавать автоматически: коммиты выполняются по просьбе Ивана.

## Bash по ходу работы

Объяснять используемые конструкции на коротких примерах. Например,
`"$@"` передаёт аргументы по отдельности, сохраняя пробелы внутри каждого.
`exec` заменяет текущий процесс запускаемой программой: обёртка не остаётся
лишним процессом и передаёт её код завершения. Оба приёма используются в установщиках.
