# video-tools — правила работы

Общаться с Иваном по-русски. Иван работает один; здесь разработка и личное использование инструментов. По ходу задач кратко объяснять полезные конструкции Bash, не превращая работу в лекцию.

## Обязательные ограничения

- Боевые прогоны обработки запускает Иван. На настоящих папках разрешён только
  пробный прогон `-n`, который ничего не пишет. Результат работы агента — готовая команда.
- Исходники неприкосновенны: не перезаписывать и не удалять содержимое `src/`.
  Новые версии результатов сохранять отдельно; не заменять чужие файлы.
- Проверки обработки — в `scratchpad/` на 2–3 коротких клипах, подключённых
  симлинками. Учитывать запись результатов: родительская папка клипа должна быть
  тестовой, не передавать реальную папку или симлинк на неё вместо тестовой.
- Всё локально; предпочитать офлайн там, где это имеет смысл. Распознавание только
  локальное, без облачных API. Сеть для исполняемых инструментов — только установка.
- Конвейеры строить в терминале; GUI не использовать. Сначала ручная обкатка,
  затем осознанная автоматизация.
- В репозитории только общие инструменты, инструкции и небольшие примеры.
  Частные расшифровки, идеи, решения и разовые скрипты — в папке видеопроекта.
  Если перенос пока невозможен, создать временную `migration/` с README и картой переноса;
  после завершения удалить временную папку и ссылки на неё.
- Не затирать существующие незакоммиченные изменения. Не коммитить без просьбы Ивана.

## Как развивать репозиторий

- Иерархия: направление → тип → инструмент. У каждого инструмента своя папка
  с README, реализацией и при необходимости установщиком, примерами и проверками.
  Не создавать пустые направления заранее.
- Python — для данных и вычислений; Bash — для команд и небольших конвейеров.
  Сохранять работающие реализации; переписывание ради языка не требуется.
  Сценарии для macOS совместимы с Bash 3.2.
- Сразу отделять различия ОС, работать с пробелами в путях и явной UTF-8.
  Не объявлять Windows/Linux поддержанными без проверки.
- Перед экспериментом определить результат и критерий проверки. После него
  решить: оставить в проекте, обобщить, отложить или прекратить.
- Указывать готовность и незакрытые проверки. Обновлять корневой каталог,
  README инструмента и ROADMAP вместе с изменениями.
- В документации оставлять актуальную версию «делать так». История решений и
  обоснования выбора — в истории коммитов. При переводе инструмента в «Готов»
  чистить рабочие заметки, устаревшие варианты и завершённые задачи ROADMAP.
- Индивидуальные обёртки команд в корне не добавлять. Текущие команды — в папках
  инструментов; будущая единая точка входа — `vt`.
- `vt`, venv и управление версиями Python пока не реализовывать: принципы
  согласованы, внедрение — по необходимости, см. документ структуры.
